# Public claims register (Access Independence / MapAble)

This register governs public, sales and Canva materials. It does **not** assert WCAG conformance.

**No WCAG 2.2 AA (or any WCAG) conformance claim is authorised** until a formal audit against a defined scope supports it.

## Status labels (use exactly)

| Label | Meaning | May be marketed as accessible? |
| --- | --- | --- |
| Live | Production behaviour with real users and real evidence pathways | Only with evidence class below |
| Pilot | Limited cohort; incomplete coverage | No blanket “accessible” claim |
| Demonstration | Product demo; may use synthetic or partial data | Must say Demonstration |
| Synthetic | Generated or fixture data | Must say Synthetic |
| Community reported | Unverified participant/community report | Not “verified” |
| Provider reported | Organisation-supplied claim | Not independently verified |
| Independently verified | Third-party or MapAble audit with date and method | May say Verified for that fact only |
| Unknown | No current evidence | **Never** market as accessible |

## Approved term meanings

| Term | Approved meaning |
| --- | --- |
| Accessible | A specific feature meets a stated requirement for a stated user need, with evidence class disclosed |
| Confirmed | Typed evidence exists in state `confirmed`, current, and not disputed |
| Verified | Confirmed **and** verification method + verified-at are present |
| Current | Evidence has not expired and is not superseded/disputed |
| Access Fit | Match between a person’s stated requirements and place facts; Unknowns reduce fit, never inflate it |
| No known barrier | Only when critical facts are Confirmed available **and** no Unavailable barrier is recorded — never from Missing/Unknown |
| Unknown | Missing or non-confirming evidence; not negative proof and not accessibility |

## Canva / public-content risks requiring owner updates

Do **not** edit external Canva files from this repository. Owner should update the following:

1. Remove or qualify any phrase **“WCAG-compliant design”** until a scoped formal audit exists.
2. Remove or qualify **“definitive”** and **“real wheelchair accessibility”** where they imply complete disability coverage or universal guarantees.
3. Label every place fact and hero claim with one of: Live / Pilot / Demonstration / Synthetic / Community reported / Provider reported / Independently verified.
4. Mark pitch decks that still contain placeholder founders, advisors, pilot regions or unsupported metrics as **DRAFT — not for publication**.
5. Ensure “Unknown” never appears as a green/accessible state in marketing graphics.
6. Replace any implied emergency monitoring language; MapAble does not provide emergency response.

## Product claims currently safe (when scoped)

- First-party Accessibility Panel (preferences) — no third-party overlay.
- Access Passport shares **functional requirements** only with **verified organisation recipients** under consent.
- Access Preflight keeps missing facts as **Unknown** and does not infer from floor plans, staff training, scores or vague notes.
- Barrier reports support drafts and moderated provider assignment; anonymous submissions are rate-limited.

## Product claims not authorised

- Whole-product WCAG 2.2 AA compliance.
- Universal door-width / regulatory guarantees from guidance thresholds alone.
- Platform-wide provider barrier inbox without organisation assignment (fail-closed until place→org ownership exists).
