# Release gates and maturity

## Current local verification

- [x] Source library written in TypeScript with no third-party runtime libraries.
- [x] Strict TypeScript compilation completed in the authoring container.
- [x] Deterministic synthetic scenario demonstration runs.
- [x] Node built-in tests cover consent, evidence, matching, routing,
      dependencies, gap suppression, equity, scheduling, funding and label invariance.
- [x] License, design contract, architecture handoff and threat model included.
- [ ] Independently reviewed or security audited.
- [ ] Validated against live service/provider evidence.
- [ ] Lived-experience co-designed and assessed.
- [ ] Connected to real authentication, consent and verification services.
- [ ] Accessibility testing of any production-facing UI.
- [ ] Human incident, complaint, appeal and fallback procedures implemented.
- [ ] Data protection impact assessment completed.
- [ ] Current legal/NDIS/transport/funding obligations reviewed for use case.
- [ ] Load tests and production observability completed.
- [ ] Australian data residency and subcontractor flows verified if required.
- [ ] Authorised real-data pilot and release owner recorded.

## Stop conditions

No real-data pilot unless identity and consent are enforceable on the server,
verification sources are audited, incident handling and withdrawal work, and
participant confirmation cannot be bypassed.

No public 'accessible route' claims without verified path coverage and a current
conditions check. No published small-area service gap data without independent
re-identification assessment and lawful publication authority.

No real worker assignment until employment/work health/safety, verified worker
screening/competence where applicable, breaks, shift limits and transactional
conflict handling are implemented and reviewed.

No claim that the software itself is NDIS registered, clinically approved,
compliant with the NDIS Practice Standards or objectively politically neutral.
